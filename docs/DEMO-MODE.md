# 데모 모드 설계·실행

공개 데모 경로: https://likelion-1team-fe.vercel.app/demo . 로그인 없이 체험할 수 있습니다. 로그인 화면의 데모 체험 링크로도 진입합니다.

로컬 실행: `npm run dev -- --host 127.0.0.1 --port 5173` 후 http://127.0.0.1:5173/demo 에 접속합니다.

## 운영 분리

- `/demo` 진입 시 운영 AuthProvider를 마운트하지 않습니다. 로그인·쿠키 갱신·사용자 조회·업무 API를 호출하지 않습니다. 실제 로그인 세션을 로그아웃하거나 변경하지 않습니다.
- 운영 저장소·식별자를 사용하지 않는 전용 합성 모델과 독립 화면입니다. 이 데모로 운영 화면의 API 연동 성공을 입증하지 않습니다.
- 선택·분석 결과·반응·가이드 지정 상태는 React 메모리에만 있습니다. 새로고침·데모 초기화 시 지워집니다. 초기화는 운영 서버 데이터를 삭제하지 않습니다.
- 제공한 작은 JSON 표식 파일만 받습니다. 실제 대화 파일·ZIP·계정 정보는 필요하지 않습니다. 내장 파일 불러오기 버튼으로 파일 선택 없이도 시연할 수 있습니다.
- 데모임을 상시 표시하며 실제 서비스로 나가는 링크는 페이지를 새로 엽니다. 실제 서비스 진입 후에는 정상 인증 흐름이 적용됩니다.

## 합성 데이터

| 대화 | 유형 | 개선 포인트 |
| --- | --- | --- |
| 신규 고객에게 제안 메일 작성 | MISSING_CONTEXT | 고객·가격·체험 기간·출력 형식 제공 |
| 반복 수정한 제안서 요약 | LONG_CONVERSATION | 흩어진 최종 조건 정리 |
| 짧은 안내 문장의 표현 수정 | OVERSPEC_MODEL | 가벼운 모델로 요구 품질 비교 |

개선 전/후 프롬프트, 근거 턴, 취소 가능한 반응을 제공합니다. 생성된 피드백에는 선택하고 성공한 대화만 포함합니다. 실제 효과·비용 절감량은 주장하지 않습니다.

분석은 약 2.5초의 시뮬레이션입니다. 전체 성공, 마지막 선택 항목 시간 초과(부분 성공), 전체 모델 설정 실패를 지원합니다. 부분 성공은 2건 이상 선택해야 실행됩니다. 화면 이동 중에도 진행하지만 초기화하면 진행과 결과가 사라집니다.

팀 성과는 방금 분석과 독립된 과거 주간 집계입니다. 기여자 6명, 확인 48건, 성공 36건, 오류 수정 재작업 12건, 성공 업무 토큰 72,000개로 구성합니다. 성공 업무당 2,000토큰·성공률 75%·재작업률 25%가 서로 일치합니다. 기여자 4명 상태를 선택하면 수치와 추이를 숨깁니다. 실제 집계 산식이나 공개 정책 검증을 대신하지 않습니다.

가이드는 별도 공유 승인이 끝난 합성 사례 1건으로 시작합니다. 팀원은 열람하고, 팀장 역할로 바꾸면 지정·해제할 수 있습니다. 개인 피드백의 공유 승인·비식별 처리를 구현한 것으로 간주하지 않습니다.

## 시연 순서

1. 데모 파일 다운로드 후 파일 선택, 또는 내장 합성 파일 불러오기.
2. 대화 1~3건 선택 → 모두 성공 → 분석 시작.
3. 생성된 피드백 → 상세 → 개선 프롬프트·근거 확인 → 반응 선택/취소.
4. 팀 성과 → 과거 합성 집계·추이 → 기여자 4명 비공개 상태 전환.
5. 개선 가이드 → 시연 역할을 팀장으로 변경 → 가이드 해제/재지정.
6. 업로드에서 부분 성공·전체 실패 재시도 또는 데모 초기화.

자동 검증은 데모 업로드·선택 범위·피드백·반응·가이드 권한·비공개 집계·불일치 파일 거절·부분/전체 실패·진행 중 초기화·새로고침 초기화·모바일 너비 및 운영 `/api/` 요청 0건을 확인합니다.

## 실제 창 시연에서 보완한 점

- 팀 성과 공개/비공개 전환과 팀장 가이드 해제·재지정을 실제 Chrome에서 확인했습니다.
- 메뉴 이동 시 이전 화면의 스크롤 위치가 남아 제목이 가려지는 문제를 수정했습니다. 이동한 화면의 제목에 키보드 초점을 두고 상단으로 이동합니다.
- 가이드가 없을 때 팀장에게도 역할 전환을 안내하던 문구를 현재 역할에 맞게 수정했습니다.
- 가이드 지정·해제 후 변경 결과와 데모 메모리 반영 사실을 표시합니다. 해제 후 팀원 역할에서도 빈 상태를 확인하는 회귀 검증을 포함합니다.
- 로컬 검토 후 사용자의 후속 요청에 따라 동일 데모 변경을 기존 보완 브랜치에 푸시하고 Vercel 프로덕션으로 배포합니다. main 병합·Git 자동 배포 연결은 별도 작업입니다.
