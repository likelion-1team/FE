# AI 업무 온보딩 · FE

배포 주소: **https://likelion-1team-fe.vercel.app** · 배포 코드 `35eee75` (2026-11-25). 실제 서버 확인 범위와 로그인 오류는 [API 통합 기록](docs/API-INTEGRATION.md#vercel-실배포-확인)에 기록했습니다.

Figma의 팀원·팀장 화면을 React 19, TypeScript, Vite, React Router, TanStack Query와 일반 CSS로 구현했습니다. 초기 저장소는 README만 있었으며, 현재 배포된 `/api/v1` 계약을 기준으로 연동합니다. 목업 데이터는 E2E 테스트에만 있으며 서비스 화면에 예시 수치를 넣지 않습니다.

## 실행

Node.js 24 LTS와 npm을 사용합니다.

```sh
npm ci
npm run dev
```

기본 주소는 `http://127.0.0.1:5173`입니다. `.env.example`을 `.env.local`로 복사하면 접속 설정을 변경할 수 있습니다. 기본 `/api/v1` 요청은 Vite 프록시를 통해 `https://t0k1.duckdns.org`로 전달합니다. 실제 계정으로 회원가입 또는 로그인한 뒤 팀을 선택하세요. 소스와 환경 변수에 비밀번호·토큰을 넣지 않습니다.

```sh
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run check:api
```

`check:api`는 공개 OpenAPI와 비인증 `/users/me` GET만 검사합니다. 브라우저 시나리오는 네트워크 응답을 가로채는 테스트이며 운영 서버에 계정·팀·분석 데이터를 만들지 않습니다.

현재 백엔드는 팀원의 TEAM 조회를 403으로 제한할 수 있습니다. 팀원 메뉴에는 팀 성과 진입점을 제공하되 실제 403을 안내하며, ME 응답을 TEAM으로 둔갑시키지 않습니다. 현재 성과 응답은 v4의 본인 확인 지표가 아니라 기존 분석 지표이므로 화면에도 기존 명칭과 분석 기준임을 표시합니다.

Figma의 샘플 차트는 `docs/design-reference/personal-trend.svg`로 보관했습니다. 실제 차트는 API 수치로 그리며, 누락·표본 부족을 0이나 연결 선으로 채우지 않습니다. IBM Plex Sans KR는 패키지에서 로컬 번들로 제공합니다.

## 배포

`npm run build` 결과물은 `dist/`입니다. Vercel에서는 포함된 `vercel.json`이 `/api/*`를 HTTPS 백엔드로 프록시하고 나머지 경로를 SPA로 처리합니다. GitHub Pages 단독 정적 호스팅은 이 프록시 설정을 지원하지 않습니다.

다른 호스팅은 `/api/`를 같은 백엔드로 프록시하고, 클라이언트 경로에 `index.html` fallback을 설정해야 합니다. `npm run preview`는 정적 산출물 확인용이며 운영 프록시를 대신하지 않습니다. 직접 외부 API 주소를 `VITE_API_BASE_URL`로 사용하면 백엔드의 정확한 Origin 허용, 쿠키·CORS 구성이 필요합니다.

## 인증·데이터 처리

- accessToken과 구버전 refreshToken은 메모리에만 보관합니다. localStorage/sessionStorage/URL에 저장하지 않습니다. JSON 토큰 배포에서는 새로고침하면 다시 로그인합니다.
- 로그인 응답에 refreshToken이 있으면 기존 JSON 갱신, 없으면 credentials 요청의 HttpOnly 쿠키 갱신을 사용합니다. `VITE_AUTH_TRANSPORT=json`은 JSON 모드 강제 설정입니다. 서버의 쿠키 전환 배포·Origin 설정을 별도로 확인하세요.
- 동시 401은 한 번만 갱신하며, 재시도 실패 시 로그인으로 돌아갑니다. 로그아웃 중 도착한 이전 응답으로 세션을 복구하지 않습니다.
- 팀 전환·로그아웃 때 요청과 개인 캐시를 정리합니다. FE 경로의 member/leader 문자열을 신뢰하지 않고 서버의 myRole을 적용합니다. 실제 데이터 접근은 서버가 최종 검사합니다.
- 로그아웃은 서버 응답보다 먼저 로컬 접근을 차단합니다. `ai-work:logout-state`에는 비밀이 아닌 로그아웃 의사·진행 상태만 저장하며, 다른 탭에도 전달합니다. 서버 종료에 실패해도 자동 쿠키 복구를 막고 로그인 화면에 실패·재시도를 안내합니다. 명시적으로 다시 로그인하면 이 표식을 지웁니다. 서버 세션 자체의 폐기는 백엔드 확인이 필요합니다.
- 기본 요청 20초, 갱신 10초, 로그아웃 8초, 파일 업로드 90초로 대기 시간을 제한합니다. 화면 이탈에 의한 요청 취소도 유지합니다.
- 화면에서 사용하는 API 응답은 런타임 구조 검사를 거칩니다. 필수 배열의 null·누락을 빈 목록으로 바꾸지 않고 오류·재시도로 안내하며, 예기치 못한 렌더 오류에는 복구 화면을 표시합니다.
- 공유·가이드는 보이는 화면에서 15초마다, 화면 복귀·재연결 시 다시 조회하고 복사 직전에도 공유 상태를 확인합니다. 다른 사용자의 철회를 즉시 전파하려면 백엔드 이벤트가 추가로 필요합니다. 이미 복사한 정보의 회수까지 보장하지는 않습니다.
- 모든 오류를 빈 목록이나 성공으로 바꾸지 않습니다. 저장·분석 요청은 자동 반복하지 않습니다. 멱등 키 헤더를 함께 보내지만 구버전 서버가 중복 방지를 보장한다는 뜻은 아닙니다.
- 전체 문서를 HTML로 삽입하지 않습니다. 원문은 React 텍스트로 이스케이프합니다. 사용자 콘텐츠·토큰을 로그에 출력하지 않습니다.

백엔드와의 차이 및 후속 작업은 [API 통합 기록](docs/API-INTEGRATION.md)을 참고하세요.

이메일 중복 확인 기본값은 GET입니다. 기존 POST 서버를 명시적으로 대상으로 할 때만 `VITE_EMAIL_CHECK_METHOD=POST`로 빌드하세요. 오류 시 임의로 요청 방식을 바꿔 반복하지 않습니다.

## 2026-11-25 계약 보완

- 분석 기준은 단일 taskType과 성공·실패·판정 불가 조건 배열을 사용합니다. 수정 요청은 expectedVersion을 보내고 409 시 입력을 유지한 채 최신 기준 재확인을 안내합니다.
- 업로드 후 후보 목록을 page=1 기준으로 검색·페이지 조회합니다. 기본 선택 해제, selectable·중복 상태·서버의 선택 건수 제한을 적용하며 분석 요청에는 selectionId와 settingsVersion을 보냅니다.
- 분석 접수는 202와 analysisId를 사용합니다. 서버의 pollAfterSeconds에 따라 조회하고 종료·오류·화면 이탈 시 주기 조회를 중단합니다. 부분 성공과 실패 항목, 피드백 링크를 구분합니다. 같은 분석 요청 재시도에는 같은 본문·멱등 키를 사용합니다.
- 업로드 이력은 기존 page=0·content 계약을 유지합니다. 서버 이력 응답에 analysisId가 없어 새로고침 후 업로드 이력만으로 분석 상세를 복구할 수 없습니다. 현재 메모리에 접수 정보가 남은 경우 연결하고, CONSUMED를 분석 완료로 표시하지 않습니다.
- 목표·결과 확인·재작업 확인 API는 서버에 추가됐으나 이번 작업은 위 네 흐름에 한정합니다. 해당 화면, 활용 이벤트·비식별 공유 승인·삭제는 후속 작업입니다.
- 브라우저 회귀는 모의 API를 사용합니다. 실계정 인증·업로드·분석 완료 검증과 구분합니다.

## 실계정 시연 결과 (2026-11-25 오후)

실계정에서 발견한 팀·팀원 페이지 응답, 확인 기반 성과·필터, 업로드 메타데이터·이력, 개인 피드백·원문·가이드의 변경 계약을 보완했습니다. 이력에 analysisId가 제공되므로 해당 계약에서는 새로고침 후 분석 상세 진입도 지원합니다.

제공된 6개 테스트 계정의 로그인, Chrome의 기본 두 역할 로그인·쿠키 복원, 별도 시연 팀(teamId=5) 생성·팀원 추가·역할별 화면·빈 상태 조회를 확인했습니다. 기존 팀 4는 변경하지 않았습니다. 기준 저장이 백엔드 직접 호출에서도 500으로 실패해 실제 파일 업로드·분석 완료는 아직 검증하지 못했습니다. 자세한 재현 정보는 [통합 기록](docs/API-INTEGRATION.md#진행을-막는-백엔드-오류)에 있습니다. 회귀 테스트는 단위/컴포넌트 28개·브라우저 28개가 통과했습니다.
